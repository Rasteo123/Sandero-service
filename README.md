# Sandero-service

Скилл Claude Code с RAG-поиском по документации **Renault Sandero II /
Sandero Stepway II** (платформа X52 Ph2, 2014+; электрика общая с Logan II).
Отвечает на вопросы по эксплуатации, обслуживанию, **ремонту** и электрике
**со ссылкой на конкретную страницу документа**.

```
$ python3 .claude/skills/sandero-service/scripts/search.py "прокачка тормозной системы" --top 1

Запрос: прокачка тормозной системы   найдено фрагментов: 1

[1] Renault Sandero II — сервисный мануал (Workshop Repair Manual 2012-2016, ENG) —
    BRAKING CIRCUIT BLEED — PDF-стр. 253-257 — фрагмент 3 из 4
    id=service_manual:u58:2  score=16.85
   … Fit the bleed containers to the six bleed screws of the callipers. Undo the
   calliper bleed screws: front left-hand, front right-hand, rear left-hand, rear
   right-hand. Open the circuit between the bleed screw and brake fluid reservoir
   and allow the liquid to run until all the air bubbles have been released …
```

Русский вопрос находит ответ в англоязычном сервисном мануале — это делает
словарь кросс-языковых синонимов, а не перевод запроса моделью.

Сервисный мануал целиком (83 МБ) коннектор Google Drive не отдаёт и не
разбирает: владелец разбил его на 15 частей по 250 страниц, а самые крупные
из них пришлось разрезать ещё раз — практический предел выгрузки около
6,3 МБ на файл. Мануал проиндексирован полностью, все 3508 страниц.

## Как это работает

Поиск не требует ни сети, ни зависимостей, ни ключей API: BM25 поверх
подготовленного корпуса, индекс собирается в памяти за доли секунды.

- **Атомарная нарезка.** Единица корпуса — законченная процедура ремонта
  или раздел руководства целиком, а не страница. Границы берутся из
  разметки издателя, а не угадываются по тексту: у сервисного мануала это
  **закладки PDF**, у русского руководства — идентификатор раздела из
  исходной вёрстки, напечатанный на каждой странице, у английского —
  заголовки. Название, если типография не напечатала его на странице
  (например, на таблицах крепления детских кресел), подставляется из
  **оглавления самого документа**. Длинная единица делится по границам
  абзацев, но каждая часть несёт название единицы, а ссылка указывает
  диапазон страниц — фрагмент никогда не остаётся без контекста.
- **Морфология.** Стеммер Портера для русского и облегчённый для
  английского с раздельными минимумами длины основы: окончание
  множественного числа безопасно на коротком слове (`pads` → `pad`), а
  глагольное `-ed` нет (`bleed` не должно стать `ble`).
- **Расширение запроса по понятиям.** Словарь синонимов срабатывает
  **фразой целиком**: «замена масла» не выстрелит на запросе «замена
  сцепления». Каждое слово запроса со своими синонимами образует понятие;
  внутри понятия синонимы конкурируют, а не складываются, и документ
  обязан закрыть все понятия запроса — иначе страница про замену ламп
  выигрывала бы у процедуры про сцепление одним словом «замена».
- **Кросс-языковые пары.** «замена X» в мануале называется «X REMOVAL -
  REFITTING», «прокачка» — «bleed», «сцепление» — «clutch». Благодаря этому
  русский вопрос доходит до английского документа.
- **Ранжирование.** К BM25 добавлены надбавка за попадание понятия в
  название единицы (для процедурного документа заголовок — сильнейший
  признак), надбавка за фразовую близость и предпочтение фрагментов с
  числом, когда спрашивают момент затяжки.
- **Опечатки.** Незнакомое слово подтягивается к словарю индекса по
  символьным триграммам: «давлени в шынах» находит «давление в шинах».
- **Иллюстрации.** Растровые схемы не ищутся сами по себе, поэтому их
  легенды и таблицы предохранителей перенесены в корпус текстом. Сами файлы
  лежат в скилле (`assets/wiring/`), и поиск печатает готовый путь: схему
  положено показать, а не пересказать словами. Страницы с чертежами
  отрисованы заранее: главы 4-5 руководства и 670 страниц сервисного
  мануала по темам, которые делают руками. Кузовной ремонт, окраска и
  дизель отсеяны, страницы без рисунков — тоже: их текст и так в корпусе.
  Всё прочее рендерится по требованию скриптом `page_image.py`.
- **Применимость к двигателю.** Корпус собран из разных изданий, и они
  покрывают разные моторы. Код двигателя в запросе — или профиль автомобиля
  из `data/vehicle.json` — отсекает документы, которые его не покрывают, и
  поиск объясняет, почему. Охват выведен из самого корпуса: сервисный мануал
  перечисляет D4F, K4M, K7M и K9K в своих же разделах спецификаций и ни разу
  не упоминает H4M. Схемы двигателя размечены точнее, до мотора: 8V — это
  K7M, 16V — K4M, поэтому по K7M не выдаётся распиновка ЭБУ от K4M.

## Использование

```bash
S=.claude/skills/sandero-service/scripts/search.py

python3 $S "как проверить уровень масла"
python3 $S "замена сцепления" --doc service_manual
python3 $S "момент затяжки болтов колеса" --top 8
python3 $S "какой предохранитель на прикуриватель" --doc wiring
python3 $S "давление в шинах" --lang ru --chapter 4
python3 $S --list-sources
```

В сессии Claude Code скилл вызывается сам, когда речь заходит о Sandero;
явно — `/sandero-service`.

## Тесты

```bash
python3 -m unittest discover -s tests -v
```

52 теста: морфология и токенизация, разбор страниц обоих форматов PDF,
атомарная нарезка, расширение запроса и ранжирование, применимость к
двигателю, целостность корпуса и эвал — 45 вопросов. Для одних проверяется,
что нужный раздел попал в топ-5, для других — что запрещённый результат в
выдачу **не** попал: процедура от чужого мотора опаснее, чем отсутствие
ответа. Эвал — гейт качества: после изменений в чанкинге или
ранжировании он должен оставаться зелёным.

## Пересборка корпуса

```bash
pip install -r requirements.txt   # pymupdf, нужен только для сборки
python3 .claude/skills/sandero-service/scripts/ingest.py --stats
```

`corpus/` в git не хранится (бинарники и авторские права). Восстановить
исходники можно в сессии Claude Code с подключённым коннектором Google Drive:

1. Попросить Claude скачать файлы по `drive_file_id` из `data/sources.json`
   инструментом `download_file_content` — большие ответы коннектор
   складывает на диск в каталог `tool-results`.
2. Разложить их по местам:

   ```bash
   python3 .claude/skills/sandero-service/scripts/drive_import.py <каталог tool-results>
   ```

## Дополнить корпус

**Руководство по ремонту Logan II.** Текстового слоя нет, нужен OCR:

```bash
ocrmypdf -l rus+eng --force-ocr corpus/pdf/Renault_LOGAN_II.pdf corpus/pdf/logan2_ocr.pdf
```

Затем добавить запись в `data/sources.json` с `"indexed": true`, пересобрать
корпус и дописать в `tests/eval_queries.jsonl` пару запросов по новым темам.

## Применимость: чего корпус не покрывает

**H4M (Nissan HR16DE), который ставили на Sandero II с 2016 года, ремонтной
документацией корпуса не покрыт.** Сервисный мануал издан на 2012-2016 и
этот мотор не застал; электросхемы относятся к K-серии — в их легенде есть
регулятор холостого хода, отдельный агрегат, которого у H4M с электронной
дроссельной заслонкой нет.

Это не мелочь: привод ГРМ у H4M цепной, а мануал описывает замену ремня.
Без проверки применимости запрос «замена цепи ГРМ H4M» возвращал заводскую
процедуру по ремню от другого двигателя — с моментами затяжки и убедительным
видом. Теперь такой запрос отсекает неприменимые документы и говорит, что
данных нет.

Профиль автомобиля владельца задан в `data/vehicle.json` — Sandero II
(X52), рынок RU, двигатель **K7M** — и применяется к каждому запросу. Этот
мотор корпус покрывает полностью, так что пробел с H4M конкретно этой машины
не касается. Для другого автомобиля достаточно поменять `engine` в профиле.

Чем закрывать пробел по H4M: заводское руководство Nissan для HR16DE
(механика двигателя, цепь ГРМ, ГБЦ), ремонтная документация LADA XRAY (тот
же H4M в паре с JH3) и руководство NU993-11 редакции 2017 года вместо
нынешнего 2019-го. Ни один из этих источников в корпус пока не добавлен.

## Оговорка

Скилл отвечает только тем, что нашёл, и обязан говорить, когда ответа в
корпусе нет. Моменты затяжки и процедуры он берёт из заводского мануала и
цитирует со страницей — но проверять критичные значения по бумажному
оригиналу всё равно стоит. Работы, связанные с тормозами, подушками
безопасности и топливной системой, документация прямо адресует сервисной
станции; эти предупреждения скилл переносит в ответ.
